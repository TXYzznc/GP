## Context

当前 COG 的数值系统基于网易数值理论（战斗力守恒定律：FC = HP × DPS），参考阴阳师的品质分级和进阶系统。但现状存在问题：

- **属性分布混乱**：棋子三阶属性倍数差异巨大（后羿 1.0→1.45→2.0，嫦娥 1.0→14.0→19.3）
- **升阶成本过低**：10/20 EXP，击败一个棋子就升级，缺乏成就感
- **品质系统未规范**：棋子虽有品质字段，但未建立统一的属性标准模型

已有基础：3 阶制（一、二、三阶）、4 档品质（蓝、紫、金、炫彩）、完整的 DataTable 系统。

## Goals / Non-Goals

**Goals：**
1. **规范棋子属性** - 所有棋子按照线性倍数（1.0x → 1.6x → 2.4x）和品质点数（2.4/2.7/3.0/3.3）标准化，使品质间的战斗力差异清晰（约 2.74 倍）
2. **调整升阶经验** - 改为 85/150 EXP，确保需要 4 场左右三阶棋子战斗才能完成全部进阶，增强成就感
3. **配置表规范化** - 完成 SummonChessTable、ChessAdvanceTable 等核心表的修改，为后续系统奠定基础
4. **验证平衡性** - 通过 FC 公式验证新数值的合理性

**Non-Goals（暂不实现）：**
- 宝物系统的逻辑实现（仅做配置表设计）
- 宝物强化成本优化（先保留原设计）
- 战斗装备系统实现（仅做配置设计）
- 宝物副属性的具体掉率算法（先保留通用机制）

## Decisions

**1. 线性倍数 vs 指数增长**
- **决策**：采用线性倍数 1.0x → 1.6x → 2.4x
- **理由**：符合网易数值理论，避免高阶爆炸，易于设计平衡；阴阳师也采用线性增长
- **替代考虑**：指数增长（1.0 → 1.5 → 2.5）会导致三阶过强，不利于多阶级混战

**2. 品质点数制 vs 固定属性值**
- **决策**：采用三维属性点数制（2.4/2.7/3.0/3.3），每个品质的三维属性和固定
- **理由**：提高棋子平衡的判断速度，参考阿阴阳师的"式神总属性值"概念，易于设计新棋子
- **替代考虑**：固定属性值（如攻击 10、生命 400）难以统一评估，容易出现"某个品质过强"的问题

**3. 升阶经验 85/150 vs 其他值**
- **决策**：一升二 85，二升三 150（总 235）
- **理由**：击败一个三阶棋子奖励 60 EXP，需要 ~4 场战斗完成全部进阶；对标产业标准（阴阳师升级也需多次）
- **计算根据**：曲线公式 EXP(n) = 50 + 30n + 5n²，验证 1→2: 85，2→3: 150
- **替代考虑**：值过低（10/20）没有成就感，值过高（200/300）玩家无法快速体验

**4. 棋子品质与进阶的分离**
- **决策**：品质（蓝/紫/金/炫彩）和阶级（一/二/三）是独立维度，不是叠加的
- **理由**：避免复杂度爆炸；棋子初获得时品质固定，不因阶级而改变
- **示例**：紫色棋子进阶后仍是紫色，只是属性倍数增加 1.6 倍

**5. 升阶成本实现延后**
- **决策**：升阶成本（50 金币/200 金币 + 1个灵石）先配置表化，逻辑实现放在 Phase 2
- **理由**：降低 Phase 1 复杂度，确保基础数值系统先验证；Phase 1 专注于属性标准化和经验调整

## Risks / Trade-offs

| 风险 | 影响 | 缓解方案 |
|------|------|--------|
| **属性修改影响现有战斗** | 玩家的当前棋子战斗力会大幅改变，可能导致关卡难度突变 | 建议结合游戏版本迭代，同时调整敌人难度；或提供数据迁移脚本保持相对平衡 |
| **升阶经验上升** | 中期玩家进度变慢，可能产生不适 | 补偿初期玩家，或提供加速活动；通过运营手段平缓过渡 |
| **品质点数制约束太强** | 未来新棋子设计时缺乏灵活性 | 允许 ±0.1 的波动；超模棋子允许 3.3-3.5（Boss 级别） |
| **线性倍数可能不够刺激** | 玩家感觉三阶提升不足 | FC 公式验证显示 2.4 倍已足以改变战局；可通过技能设计补偿 |

## Migration Plan

**Phase 1 - 配置表规范化（1-2 周）**

1. **修改 SummonChessTable**
   - 遍历所有棋子，按品质和职业类型重新分配三维属性点
   - 验证：品质点数和 = 预期值（2.4/2.7/3.0/3.3）
   - 验证：三阶倍数 = 2.4x
   - 手工计算几个代表性棋子，用 FC 公式验证战斗力差异

2. **修改 ChessAdvanceTable**
   - 将 RequiredEXP 从 [10, 20] 改为 [85, 150]
   - 确认只有两行数据需要改（棋子 ID 1 和 4）

3. **设计宝物配置数据（不立即添加到表）**
   - 列出所有需要新增的 Type=3（宝物）物品条目：ID、名称、品质、AffixPoolIds、BaseAttributes 等
   - 设计宝物副属性词条（新增到 AffixTable）：词条名称、属性类型、数值范围、权重
   - 设计宝物套装效果 Buff（新增到 BuffTable）：5 个套装及其效果

4. **设计战斗装备配置数据（不立即添加到表）**
   - 列出所有需要新增的 Type=4（装备）物品条目：ID、名称、品质、BaseAttributes、IsOnlyInGame=True 等
   - 列出装备合成配方（备忘录）
   - 定义装备掉落池和概率

5. **验证与文档**
   - 用 FC 公式验证所有品质的战斗力比例
   - 记录各棋子的新旧属性对比
   - 更新本设计文档的"实施结果"部分

**Phase 2-4 - 系统逻辑实现（后续）**
- Phase 2：宝物系统逻辑（装备、强化、副属性管理）
- Phase 3：战斗装备系统（掉落、合成、卸下）
- Phase 4：测试与平衡调优

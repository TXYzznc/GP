## 🎯 Phase 1 执行步骤（文本修改）

### 准备工作
1. 打开论文 Word 文档
2. 准备以下参考文档（放在易访问的位置）：
   - `text_content_modifications.md` - 文本修改指南
   - `detailed_thesis_modifications.md` - 修改详细方案
   - 项目代码文件（需要时参考）

### 修改 2: 补充缺失的中等数据
**优先级**: 🔴 最高 | **难度**: 中 | **预计时间**: 30-45 分钟

```
步骤：
1. 打开论文，使用 Ctrl+F 搜索 "第一、第二、第三" 或类似序号
2. 定位包含重复数据的段落
3. 按照 text_content_modifications.md 中的"修改 2"说明
4. 补充中间层级的分类
5. 验证逻辑完整性（参考修改 2 的验收清单）
```

### 修改 3: AI 相关内容具体化
**优先级**: 🔴 最高 | **难度**: 中 | **预计时间**: 45-60 分钟

```
步骤：
1. 在论文中搜索 "AI" 或 "人工智能"
2. 找到过于笼统的描述
3. 按照模板分为 3 个具体方向（战斗、探索、事件触发）
4. 补充每个方向的职责、实现技术、配置表说明
5. 添加具体应用场景示例
6. 通读确保表述清晰
```

### 修改 4: 补充外部框架模块说明
**优先级**: 🟡 中等 | **难度**: 中 | **预计时间**: 30-45 分钟

```
步骤：
1. 搜索 "GameFramework" 的提及处
2. 在该处扩展说明，补充 5-6 个核心模块
3. 对每个模块说明：职责、实现、应用场景
4. 说明业务系统与框架的关系
5. 突出分层架构的意义
```

### 修改 5: 明确设计重点
**优先级**: 🟡 中等 | **难度**: 高 | **预计时间**: 45-60 分钟

```
步骤：
1. 找到关键的设计决策处（如伤害计算、Buff 系统等）
2. 分析设计原因（通常从功能、性能、可扩展性多个角度）
3. 补充实现说明和权衡分析
4. 与其他方案对比
5. 整理成"设计选择"小节
```

### 修改 6: 补充框架模式与范例
**优先级**: 🔴 最高 | **难度**: 高 | **预计时间**: 60-90 分钟

```
步骤：
1. 找到需要补充范例的段落（通常是提及设计模式的地方）
2. 先介绍模式框架（组件模式、策略模式等）
3. 提供架构示意（文字或简图）
4. 补充配置表范例（含实际数据）
5. 说明应用流程（逐步）
6. 补充关键代码伪码
7. 说明设计优势
8. 关联其他相似应用场景
```

## 🎨 Phase 2 执行步骤（AI 图表生成）

### 准备工作
1. 准备 AI 绘图工具账号（推荐 Gemini、Claude Canvas 或其他）
2. 准备参考文档：`AI_chart_prompts.md`
3. 建立输出文件夹存放生成的图表

### 图表生成流程

**对于每个图表：**

#### Step 1: 准备 Prompt
```
1. 打开 AI_chart_prompts.md
2. 复制对应图表的完整 Prompt
3. 根据需要微调（如颜色、尺寸等）
```

#### Step 2: 调用 AI 生成
```
1. 打开 AI 绘图工具（Gemini Canvas）
2. 粘贴 Prompt
3. 生成图表
4. 根据预览调整（如有需要）
```

#### Step 3: 导出高分辨率版本
```
1. 选择 PNG 格式，300 DPI
2. 宽度设为 16-18cm
3. 导出并命名为 Figure_X_[ChartName].png
4. 保存到本地文件夹
```

## 📐 Phase 3 执行步骤（论文编辑）

### 3.1 图表插入论文

对于每个生成的图表：

```
步骤：
1. 在 Word 中，定位要插入图表的位置
2. 菜单 → 插入 → 图片（从文件）
3. 选择对应的 PNG 图表
4. 调整大小至合适尺寸（建议宽度 16cm）
5. 添加图号和标题（如 "图 2.1 系统架构总体图"）
6. 右键 → 环绕文本 → 四周型
7. 在图表下方添加说明文字（详见 3.2）
```

### 3.2 图表说明补充

**修改 7**: 图表说明补充（修改 87）

```
对于每张图表，在其下方添加说明文字（约 3-5 行）：

格式：
图 X.Y: [图表标题]
说明：[1-2句说明该图表的目的]
- [关键要素1]: [解释]
- [关键要素2]: [解释]
- [关键要素3]: [解释]

示例（图表 1）：
图 2.1: 系统架构总体图
说明：展示 Clash of Gods 游戏系统的分层架构。
- Layer 1（游戏引擎层）: 提供基础游戏引擎和框架支持
- Layer 2（核心系统层）: 包含游戏的 5 个主要业务系统
- Layer 3-4（支撑层）: 提供数据、事件、资源等基础服务

字体规范：
- 标题字号: 11pt, 加粗
- 说明文字: 10pt, 正常
- 行距: 1.15
```

### 3.3 图表尺寸统一（修改 11 和 112）

```
检查所有图表的尺寸：

1. 打开论文
2. 对每张图表进行以下检查：
   - [ ] 宽度 14-20cm（推荐 16-18cm）
   - [ ] 显示清晰，文字可读
   - [ ] 与相邻图表尺寸相近
   - [ ] 不超出页面边界

3. 对"最后几张图表"特别检查
   - 最后 2-3 张图表尺寸应完全统一
   - 如有偏差，统一调整为最适尺寸

4. 调整方法：
   - 右键图表 → 大小和位置
   - 设置统一的宽度（如 17cm）
   - 高度自适应
   - 应用到相同尺寸的图表
```

### 3.4 排版和格式调整

```
逐项检查排版：

1. 图表上下间距
   - 图表上方段落与图表间隔: 0.5cm
   - 图表下方说明文字: 紧挨图表，无间隔
   - 说明文字与下个段落间隔: 0.5cm

2. 图表与页边的对齐
   - 所有图表左边缘与页左边界对齐
   - 不居中，不缩进

3. 文字排版
   - 确保图表说明文字字号统一（10pt）
   - 列表项用符号（- 或 •）而非手工输入
   - 长句子避免过度折行

4. 页面布局
   - 避免图表孤立在页面底部（不足 3 行空间）
   - 如有问题，可在图表前添加或删除段落进行调整
```

## 🆘 常见问题

### Q1: 修改 6 涉及代码，但我对项目代码不熟悉？
**A**: 可以根据项目的系统设计文档来补充伪码。查阅 `INDEX.md` 中的相关系统设计文档，提取关键的方法名和逻辑流程。

### Q2: AI 图表生成的效果不理想？
**A**: 
1. 检查 Prompt 的措辞是否清晰
2. 尝试调整配色或布局要求
3. 如必要，可分次生成（如先生成总体架构，再生成细节）
4. 在 Prompt 中可添加 "更清晰"、"提高对比度" 等微调

### Q3: 图表插入论文后尺寸错乱？
**A**:
1. 右键图表 → 大小和位置
2. 设置固定宽度（如 17cm）
3. 高度锁定宽高比
4. 确保"换行方式"为"四周型"

### Q4: 论文修改后与其他章节不一致？
**A**: 通读全文，检查：
1. 配置表名称是否与项目一致
2. 系统名称是否与其他章节相同
3. 缩写词定义是否统一
4. 必要时更新其他相关章节以保持一致

# 变更分析和测试优先级

**生成时间**: 2026-05-09  
**范围**: 通用效果框架实现（Phase A + Phase B）

---

## 一、变更概览

### 总体修改统计
- **新增文件**: 4 个（GameEffectContext.cs、GameEffectService.cs、SynergyManager.cs）
- **修改文件**: 25+ 个
- **配置表变更**: 14 个 .xlsx 文件（新增字段、移除字段）
- **代码行数变更**: ~6385 insertions, ~5473 deletions

### 核心架构变更
```
旧架构: ItemEffectExecutor + 分散的 Buff 应用 + 后续的羁绊系统
↓
新架构: GameEffectService（统一入口）
        ├─ BuffApplyHelper（Buff 路径）
        ├─ ItemEffectFactory（自定义效果路径）
        └─ SynergyManager（羁绊系统）
```

## 二、关键变更分析

### 2.1 最高风险的变更

| 变更 | 风险等级 | 影响范围 | 关键问题 |
|------|---------|---------|---------|
| **EffectCategory 字段移除** | 🔴 高 | CombatTriggerManager | 硬编码的 EffectId 范围（301-399、101-199、201-299）需要与配置数据一致 |
| **SynergyManager 新增** | 🔴 高 | 羁绊系统全部 | 事件驱动逻辑复杂，状态管理关键 |
| **GameEffectService 作为统一入口** | 🟠 中 | 所有效果执行 | 需要检查所有效果源是否正确路由 |
| **BuffTable.IsHidden** | 🟡 低 | UI 显示 | 仅影响视觉，逻辑影响小 |

### 2.2 最容易出现的问题

#### 问题 #1: EffectId 范围与实际配置数据不符
**表现**: 某些效果无法选择或选择到错误的效果  
**根本原因**: SpecialEffectTable.xlsx 中的实际 ID 不在指定范围内  
**测试方法**: 手动检查 SpecialEffectTable.txt 数据，验证 ID 分布

#### 问题 #2: 羁绊 Buff 多次应用或未移除
**表现**: Buff 堆叠层数异常，属性加成错误  
**根本原因**: m_SynergyBuffMapping 与实际应用的 Buff 不同步  
**测试方法**: T17（反复激活/失活同一羁绊）

#### 问题 #3: 棋子羁绊条件判断错误
**表现**: 明明满足条件却未激活，或不满足也激活了  
**根本原因**: CheckChessSynergyCondition 的逻辑 OR vs AND 混淆  
**测试方法**: T11（多个棋子羁绊并存）

#### 问题 #4: 宝物羁绊系统预留接口无法使用
**表现**: 宝物装备后没有任何羁绊效果  
**根本原因**: GetTreasureSynergyIdsForChess 当前返回空列表  
**测试方法**: 等待宝物装备系统实现后测试

## 七、风险缓解策略

### 如果发现 EffectId 范围不匹配
**应急方案**: 修改 CombatTriggerManager 中的范围值，改用配置驱动（从 DataTable 读取范围）

### 如果羁绊系统有 bug
**调试步骤**:
1. 添加日志输出：每次 RefreshChessSynergies 时输出 raceCount/classCount
2. 检查 m_ActiveChessSynergies 和 m_SynergyBuffMapping 的同步
3. 验证 OnSynergyStateChanged 事件是否正确触发

### 如果效果无法执行
**检查清单**:
1. GameEffectService.Instance 是否被正确初始化（Awake）？
2. ItemManager.Instance 是否可访问（获取 SpecialEffectData）？
3. 目标 GameObject 的 BuffManager 是否存在？

# 《Clash of Gods》数值模型设计方案

> **生成日期**: 2026-05-09  
> **目的**: 建立统一的数值体系，确保所有配置表数值的逻辑一致性与平衡性  
> **范围**: 覆盖棋子属性、伤害计算、Buff机制、经验资源、难度系统、卡牌机制

---

## 第一部分：核心属性系统

### 1.1 棋子基础属性结构

**五大核心属性**（所有棋子都有）：
- `MaxHP` - 最大生命值
- `AtkDamage` - 攻击力
- `Armor` - 护甲（物伤减伤）
- `MagicResist` - 魔抗（魔伤减伤）
- `MoveSpeed` - 移动速度

**附加攻击属性**：
- `AtkSpeed` - 攻击速度（单位：次/秒）
- `AtkRange` - 攻击距离
- `CritRate` - 暴击率（0-100%）
- `CritDamage` - 暴击伤害倍率（默认1.5x）
- `SpellPower` - 法术强度
- `MaxMp` - 最大魔法值

**防御与生存**：
- `MaxShield` - 护盾值
- `LifeSteal` - 吸血率
- `CooldownReduce` - 冷却缩减

### 1.2 属性等级制系统（三阶制）

```
一阶 ─────── 二阶 ─────── 三阶
弱    10~20    强    20~30    最强
```

**现状分析**：SummonChessTable 已按三阶分别配置属性数组

**问题**：
- 二阶与一阶的属性加成比例不一致（部分棋子2倍，部分1.5倍）
- 三阶与二阶的加成比例波动大

**建议方案 A**：标准化阶级系数
```
一阶 = 1.0 倍
二阶 = 1.6 倍
三阶 = 2.5 倍
```
（基于后羿例子：400 → 580 → 800 ≈ 1.45 → 2.0，建议调整为更线性的1.6 → 2.5）

**建议方案 B**：精细化阶级系数（不同属性不同系数）
```
血量: 一阶1.0x → 二阶1.5x → 三阶2.2x
攻击: 一阶1.0x → 二阶1.6x → 三阶2.6x
防御: 一阶1.0x → 二阶1.4x → 三阶2.0x
```

## 第二部分：伤害计算系统

### 2.1 伤害类型分类

根据 CardTable，共有 3 种伤害类型：

| 伤害类型 | 值 | 减伤机制 | 数据源 | 典型场景 |
|---------|----|-----------|----|---------|
| 物理伤害 | 1 | 护甲（Armor）| 棋子AtkDamage | 普通攻击、物理技能 |
| 魔法伤害 | 2 | 魔抗（MagicResist）| SpellPower | 魔法技能、法系棋子 |
| 真实伤害 | 3 | 无减伤 | BaseDamage | 终极技能、特殊效果 |

### 2.2 伤害公式设计

#### 2.2.1 基础伤害公式

```
最终伤害 = (基础伤害 + 伤害系数 × 攻击力) × (1 - 减伤率) × 暴击倍数 × Buff倍数
```

#### 2.2.2 减伤机制

**物理伤害减伤**：
```
物伤减伤率 = Armor / (Armor + 250) ∈ [0, 0.8]

说明：
- Armor = 0    → 减伤0%      → 100% 伤害通过
- Armor = 250  → 减伤50%     → 50% 伤害通过
- Armor = 1000 → 减伤80%     → 20% 伤害通过（上限）
```

**魔法伤害减伤**：
```
魔伤减伤率 = MagicResist / (MagicResist + 300) ∈ [0, 0.75]

说明：
- MagicResist = 0    → 减伤0%      → 100% 伤害通过
- MagicResist = 300  → 减伤50%     → 50% 伤害通过
- MagicResist = 1200 → 减伤75%     → 25% 伤害通过（上限）
```

**真实伤害**：
```
真实伤害 = BaseDamage × (1 + Buff倍数)
（不受任何减伤影响）
```

#### 2.2.3 暴击系统

```
触发暴击 = if random() < CritRate:
  实际伤害 = 基础伤害 × CritDamage（默认1.5x-2.0x）
否则:
  实际伤害 = 基础伤害

说明：CritRate 范围通常为 0-100%，特殊情况可超过100%
```

#### 2.2.4 吸血机制

```
吸血量 = min(造成伤害 × LifeStealRatio, 目标最大生命值 × 0.5)

说明：
- 吸血率 0-40%（来自Buff数据）
- 单次吸血不超过目标最大生命值的50%
```

### 2.3 破甲机制（对标现有伤害计算系统）

根据 BuffTable，破甲 Buff 降低敌方防御：

**固定值破甲**：
```
目标有效防御 = max(0, 原防御 - 破甲值)
```

**百分比破甲**：
```
目标有效防御 = 原防御 × (1 - 破甲百分比)
```

**堆叠破甲**：
```
总破甲值 = 多个破甲效果叠加（上限300点，或上限80%）
```

## 第三部分：Buff 系统数值标准化

### 3.1 属性修改型 Buff 规范

根据 BuffTable，属性修改使用 JSON 格式：`{"AtkDamage":"25%"}`

**数值范围建议**：

| Buff类型 | 强度 | 攻击力 | 防御 | 移速 | 法强 | 持续时间 | 堆叠层数 |
|---------|------|-------|------|------|------|---------|--------|
| 普通增益 | 弱 | +10-15% | +10% | +10% | +10% | 8-10s | 1层 |
| 强化增益 | 中 | +20-30% | +15-20% | +15% | +15% | 10-15s | 1-2层 |
| 终极增益 | 强 | +40-60% | +25-30% | +20% | +25% | 0(永久) | 1层 |
| 普通减益 | 弱 | -10-15% | -10% | -10% | -10% | 2-4s | 1层 |
| 强化减益 | 中 | -20-30% | -15-20% | -20% | -15% | 4-8s | 1-3层 |

### 3.2 周期伤害型 Buff（DOT/HOT）

根据 BuffTable，周期伤害使用参数 `Interval` 和自定义参数：

**周期伤害公式**：
```
每次伤害 = (基础伤害 × 伤害系数 + 固定伤害) × (1 - 目标减伤率)
总伤害 = 每次伤害 × (持续时间 / 触发间隔)
```

**标准配置**：

| Buff | 伤害类型 | 每次伤害 | 触发间隔 | 持续时间 | 总伤害 | 堆叠 |
|-----|---------|---------|---------|---------|-------|------|
| 灼烧 | 固定 | 5点 | 1s | 10s | 50点 | 10层 |
| 流血 | 百分比 | 1%HP | 0.5s | 4s | 8%HP | 1层 |
| 中毒 | 百分比 | 5%HP | 1s | 15s | 75%HP | 1层 |
| 回春 | 治疗 | 50点 | 3s | 15s | 250点 | 1层 |

## 第四部分：经验与升级系统

### 4.1 玩家经验曲线

根据 PlayerDataTable，玩家等级 1-60，经验需求：

**现状分析**：
- 1级：100 EXP
- 20级：8000 EXP
- 30级：37000 EXP
- 60级：122000 EXP

**曲线公式建议**：
```
BaseExp(Level) = 100 × (1 + Level × 0.15)²

例如：
Lv1:   100
Lv10:  1500
Lv20:  6300
Lv30:  37000
Lv60:  122000
```

### 4.2 棋子经验系统

根据 ChessEXPRuleTable，棋子升阶需要 EXP：

| 升阶方式 | EXP奖励 | 说明 |
|---------|--------|------|
| 1阶敌方棋子 | 10 | 击败弱敌 |
| 2阶敌方棋子 | 25 | 击败中敌 |
| 3阶敌方棋子 | 60 | 击败强敌 |
| 经验道具 | 0 | 由道具自身决定 |

**升阶所需 EXP**（ChessAdvanceTable）：
```
1升2: 10 EXP
2升3: 20 EXP
总计: 30 EXP
```

**问题**：升阶 EXP 太低，击败3阶棋子1次即可升至三阶

**建议调整**：
```
1升2: 50 EXP (击败3阶敌方2次左右)
2升3: 100 EXP (击败3阶敌方2次左右)
总计: 150 EXP

或更激进：
1升2: 100 EXP
2升3: 200 EXP
总计: 300 EXP
```

### 4.3 来源经验公式

根据 ExpRuleTable：

**物品掉落经验**：
```
EXP = BaseExp × (1 + PlayerLevel × ExpPerLevel%)
```

| 物品品质 | 基础EXP | 等级系数 |
|---------|--------|--------|
| 普通(1) | 10 | 1.5% |
| 优秀(2) | 20 | 2.5% |
| 稀有(3) | 40 | 4.0% |
| 史诗(4) | 80 | 7.0% |
| 传说(5) | 150 | 12.0% |

**敌人击败经验**：
```
EXP = BaseExp × (1 + PlayerLevel × ExpPerLevel%) × 难度系数
```

| 敌人难度 | 基础EXP | 等级系数 | 难度系数 |
|---------|--------|--------|---------|
| 1 | 30 | 3.0% | 1.0 |
| 2 | 60 | 5.0% | 1.1 |
| 3 | 120 | 9.0% | 1.2 |
| 4 | 200 | 15.0% | 1.3 |
| 5 | 350 | 25.0% | 1.5 |

## 第五部分：难度与奖励系统

### 5.1 战斗难度系统

根据 CombatDifficultyRule 和 EnemyEntityTable：

```
难度等级 (1-10) ──> 敌人数量 ──> 敌人强度 ──> 奖励倍率
```

**当前配置**：

| 难度 | 敌难系数 | 敌人数(min-max) | 奖励倍率 | 说明 |
|------|--------|-------------|--------|------|
| 1 | 0.4x | 2-2 | 1.0x | 学习难度 |
| 2 | 0.6x | 1-3 | 1.1x | 容易难度 |
| 3 | 0.8x | 2-3 | 1.2x | 普通难度 |
| 4 | 1.0x | 2-4 | 1.3x | 困难难度 |
| 5 | 1.4x | 3-5 | 1.5x | 噩梦难度 |
| 10 | 5.0x | 5-10 | 3.0x | 地狱难度 |

**敌人强度计算**：
```
敌人属性 = 基础属性 × 敌难系数
```

例如难度1敌人（系数0.4x）：
- 基础HP 800 × 0.4 = 320
- 基础ATK 25 × 0.4 = 10
- 基础DEF 40 × 0.4 = 16

**奖励倍率应用**：
```
获得物品数 = base(1-2) × floor(奖励倍率)
例：难度5 (1.5x) → 1-2个物品，每0.3额外+1个
```

### 5.2 推荐难度指引

根据玩家等级推荐对应难度：

```
玩家等级 → 推荐难度
Lv1-10  → 难度1-2
Lv10-20 → 难度2-3
Lv20-35 → 难度3-4
Lv35-50 → 难度4-5
Lv50-60 → 难度5+
```

## 第八部分：当前数值问题与优化清单

### 8.1 棋子属性不平衡问题

**问题 1**：三阶系数不一致
- 后羿：400→580→800 (1.45x, 1.38x)
- 嫦娥：30→420→580 (14x, 1.38x) ← 严重不平衡

**问题 2**：法系棋子伤害不足
- 嫦娥 SpellPower: 0,0,0 (完全没有法伤)
- 恶魂 SpellPower: 35,50,70 (相对合理)

**问题 3**：敌人难度系数过低
- 难度5敌人仅为基础属性的1.4倍
- Boss难度与精英难度差异不大

### 8.2 经验系统数值问题

**问题 1**：棋子升阶 EXP 过低
- 击败1个3阶棋子 (60 EXP) > 升2阶需要 (10 EXP)
- 建议：1升2→50，2升3→100

**问题 2**：玩家经验梯度不平衡
- 早期 (1-10) 增长较平缓
- 后期 (40-60) 增长过陡
- 建议：调整 ExpPerLevel 系数

### 8.3 卡牌平衡问题

**问题 1**：灵力消耗不统一
- 神圣庇护 (稀有) 消耗30灵力
- 烈焰风暴 (史诗) 消耗50灵力 ← 应为60+

**问题 2**：伤害型卡牌效率差异大
- 护甲破碎：消耗45，伤害系数0，固定50伤害 ← 太弱
- 雷霆一击：消耗60，伤害系数0，固定200伤害 ← 太强

### 8.4 难度系统平衡问题

**问题**：难度1-4 之间跨度太小
- 难度系数：0.4 → 0.6 → 0.8 → 1.0（线性增长）
- 建议：改为指数增长 (0.4 → 0.7 → 1.2 → 2.0)

## 第九部分：数值设计原则与工作流

### 9.1 核心设计原则

1. **可读性**：所有数值都应该一目了然，避免复杂计算
2. **平衡性**：不同选择（输出/防守/控制）应有相同的价值比
3. **可扩展性**：新增系统时，数值公式应能兼容
4. **层级性**：稀有度、难度、等级应形成清晰的阶梯

### 9.2 工作流建议

```
第一阶段：标准化基础属性
├─ 统一棋子三阶系数 (1.0 → 1.6 → 2.5)
├─ 统一 Buff 数值范围
└─ 确定伤害减伤公式

第二阶段：调整经验与升级
├─ 修改棋子升阶 EXP 需求
├─ 调整玩家经验曲线
└─ 平衡难度与奖励

第三阶段：卡牌与战斗平衡
├─ 统一卡牌灵力消耗
├─ 调整卡牌伤害系数
└─ 测试 PvE 战斗难度

第四阶段：整体数据验证
├─ 对比各难度战斗的清除率
├─ 验证经验获取速度
└─ 收集玩家反馈，迭代优化
```

## 第十部分：实施建议

### 10.1 短期 (1-2周)

1. **修复严重失衡**：嫦娥三阶系数、法系棋子伤害
2. **统一数值规范**：Buff 范围、难度系数
3. **测试覆盖**：数值变更前后的战斗对比

### 10.2 中期 (2-4周)

1. **逐步调整**：分批修改配置表，A/B测试
2. **建立反馈机制**：记录玩家游戏时长、获胜率、资源获取
3. **数据面板**：制作实时数值仪表板

### 10.3 长期 (持续)

1. **定期评审**：每月回顾数值变化影响
2. **季节性调整**：根据内容更新调整难度
3. **社区反馈**：收集玩家建议，权衡设计

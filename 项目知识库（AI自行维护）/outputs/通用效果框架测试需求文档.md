## 一、架构变更总览

### 1.1 核心改动
- **新增**: GameEffectContext（效果执行上下文）
- **新增**: GameEffectService（通用效果执行服务）
- **新增**: SynergyManager（羁绊系统管理）
- **修改**: CombatTriggerManager（使用新框架，移除 EffectCategory）
- **修改**: ConsumableItem（使用新框架）
- **配置表**: BuffTable 新增 IsHidden 字段；SpecialEffectTable 移除 EffectCategory；SynergyTable 同步 IsTreasureSynergy

### 1.2 变更的文件清单
| 文件 | 类型 | 影响范围 |
|------|------|--------|
| GameEffectContext.cs | 新增 | 全局效果执行 |
| GameEffectService.cs | 新增 | 全局效果执行 |
| SynergyManager.cs | 新增 | 羁绊系统 |
| CombatTriggerManager.cs | 修改 | 战斗系统 |
| ConsumableItem.cs | 修改 | 消耗品系统 |
| BuffTable.cs | 修改 | UI 显示逻辑 |
| SpecialEffectTable.cs | 修改 | 数据表结构 |

## 二、GameEffectService 测试需求

### 2.1 基础功能测试

#### T1: 单目标 Buff 应用
**场景**: 消耗品使用时应用 Buff  
**前置条件**: 消耗品配置了 BuffIds  
**步骤**:
1. 使用一个消耗品，该消耗品的 SpecialEffectTable 配置了 BuffIds
2. 观察目标棋子是否正确应用 Buff
3. 检查 Buff 的持续时间、堆叠层数、图标显示是否正确

**预期结果**: ✅ Buff 正确应用

**可能的问题**:
- Buff 应用失败（BuffManager 不可访问）
- Buff ID 无效导致应用失败
- Buff 堆叠数量计算错误

---

#### T2: 多目标 Buff 应用
**场景**: 棋子羁绊激活时应用 Buff 给所有出战棋子  
**前置条件**: SynergyManager 已初始化，至少 3 个棋子出战  
**步骤**:
1. 在战斗中部署 3 个棋子
2. 通过调整或放置棋子，触发棋子羁绊（满足 RequireIds 和 RequireCount）
3. 观察是否所有出战棋子都收到了羁绊 Buff

**预期结果**: ✅ 所有目标棋子获得 Buff

**可能的问题**:
- 部分棋子未收到 Buff（遍历逻辑错误）
- 多次应用同一羁绊导致 Buff 重复
- 棋子死亡后仍尝试应用 Buff 导致异常

---

#### T3: SelfBuff 路径
**场景**: 先手效果应用 SelfBuff  
**前置条件**: SpecialEffectTable 配置了 SelfBuffIds  
**步骤**:
1. 触发战斗（遭遇战或敌方先手）
2. 检查玩家方或敌方是否收到 SelfBuff

**预期结果**: ✅ SelfBuff 应用给正确的对象

**可能的问题**:
- Caster 为 null 导致 SelfBuff 应用失败
- 玩家先手时 Caster 配置错误
- 敌方先手时未正确识别敌人

---

#### T4: 自定义效果执行
**场景**: 执行 JSON 驱动的自定义效果（如恢复生命值）  
**前置条件**: SpecialEffectTable 配置了 EffectParams（type 字段）  
**步骤**:
1. 使用包含自定义效果的消耗品
2. 验证效果是否正确执行

**预期结果**: ✅ 自定义效果生效

**可能的问题**:
- EffectParams 解析失败
- ItemEffectFactory 返回 null
- 自定义效果执行异常

---

### 2.2 效果源识别测试

#### T5: 不同效果源的路由
**场景**: 验证 GameEffectContext.Source 正确分类  
**步骤**:
1. 分别测试三种效果源：
   - EffectSource.Item（消耗品）
   - EffectSource.Synergy（羁绊）
   - EffectSource.CombatPrep（先手效果）

**预期结果**: ✅ 所有效果源正确路由

**可能的问题**:
- 效果源在某些场景下标识错误
- 日志混淆不同源的效果

---

#### T6: 效果来源追踪
**场景**: 调试 Buff 来自哪个效果  
**步骤**:
1. 应用多个不同来源的 Buff
2. 在 Buff 管理器中查看 Buff 来源标记

**预期结果**: ✅ 可清晰追踪 Buff 来源

**可能的问题**:
- 没有记录效果来源信息
- 多个相同 ID 的 Buff 难以区分

---

### 2.3 错误处理测试

#### T7: 无效效果 ID
**场景**: 使用不存在的 SpecialEffectTable ID  
**步骤**:

**预期结果**: ✅ 系统给出警告，不崩溃

**预期结果**: ✅ 系统正确处理，不崩溃

**可能的问题**:

**场景**: 部署足够数量的特定种族/职业棋子，触发羁绊  
**前置条件**: SynergyTable 配置了棋子羁绊（IsTreasureSynergy=0）  
**步骤**:
1. 在战斗准备阶段部署满足羁绊条件的棋子

3. 检查是否有 OnSynergyStateChanged 事件触发

**预期结果**: ✅ 羁绊正确激活，事件触发

**可能的问题**:
- 种族/职业统计错误（重复计数或遗漏）
- 羁绊条件判断有误
- 事件未正确触发

---

#### T10: 棋子羁绊失活
**场景**: 召回棋子，使羁绊不再满足条件  
**前置条件**: 已激活的棋子羁绊  
**步骤**:
1. 召回部署的棋子，破坏羁绊条件
2. 检查 UI 是否移除羁绊图标
3. 检查 Buff 是否被移除

**预期结果**: ✅ 羁绊失活，Buff 移除

**可能的问题**:
- Buff 未被正确移除
- UI 未更新
- m_ActiveChessSynergies 状态不一致

---

#### T11: 棋子羁绊状态管理
**场景**: 在部署过程中反复添加/移除棋子  
**步骤**:
1. 部署 3 个棋子 → 激活羁绊 A
2. 部署第 4 个棋子 → 激活羁绊 B
3. 召回第 1 个棋子 → 失活羁绊 A，B 仍激活
4. 重新部署第 1 个棋子 → 重新激活羁绊 A

**预期结果**: ✅ 所有状态转换正确

**可能的问题**:
- 重复激活导致 Buff 堆叠异常
- 失活时移除错误的 Buff
- m_SynergyBuffMapping 与实际 Buff 不同步

---

#### T12: 多个棋子羁绊并存
**场景**: 同时激活多个不同的棋子羁绊  
**步骤**:
1. 部署棋子满足条件，激活 3-5 个不同的羁绊
2. 观察所有羁绊的 Buff 是否都正确应用

**预期结果**: ✅ 多个羁绊共存，互不干扰

**可能的问题**:
- 羁绊 Buff 相互覆盖
- 失活一个羁绊时影响其他羁绊
- m_SynergyBuffMapping 容量问题

# 容器架构设计

> **最后更新**: 2026-05-12  
> **状态**: 架构设计完整，已验证通过  
> **版本**: 2.0（修复问题后的最终版）

---

## 一、架构概览

### ISlotContainer 系统层次

```
ISlotContainer（接口）
    ↓
SlotContainerBase（抽象基类）
    ├─ InventorySlotContainerImpl（背包容器）
    ├─ WarehouseSlotContainerImpl（仓库容器）
    ├─ FastBarSlotContainerImpl（快捷栏容器）
    └─ EquipSlotContainerImpl（装备栏容器框架）
```

### 核心设计原则

1. **单一责任**: MoveToXXX 方法只处理目标相关逻辑，源格子清理由 ExecuteMove 统一处理
2. **对称性**: 容器内操作支持交换（SwapSlots）；跨容器操作只支持存入/堆叠
3. **数据一致性**: 避免重复操作，清空源格子基于目标格子状态判断

### 清空源格子的统一条件

```csharp
if (success && targetContainer is not [SameContainerType] &&
    (targetIsEmpty || targetSlot.ItemId == itemId))
{
    ClearSource();
}
```

## 二、操作规则总结（最终版）

| 源 ← → 目标 | 允许 | 行为 |
|----------|------|------|
| 背包 ↔ 背包 | ✓ | 存入、堆叠、**交换** |
| 背包 ↔ 仓库 | ✓ | 存入、堆叠（不支持交换） |
| 背包 ↔ 快捷栏 | ✓ | 存入、堆叠（不支持交换） |
| 仓库 ↔ 仓库 | ✓ | 存入、堆叠、**交换** |
| 仓库 ↔ 快捷栏 | **✗** | 已禁止（违反设计） |
| 快捷栏 ↔ 快捷栏 | ✓ | 存入、堆叠、**交换** |

**设计理由**：
- 快捷栏是"背包的快速访问栏"，物品流应通过背包中转
- 不应直接与仓库交互，避免复杂的数据竞争
- 跨容器交换会导致 RemoveItem 对错误物品的操作（如多个格子含同种物品）

## 三、容器实现清单

| 容器 | 文件 | 职责 |
|------|------|------|
| 背包 | InventorySlotContainerImpl.cs | 处理背包内交互规则，支持与仓库、快捷栏的单向操作 |
| 仓库 | WarehouseSlotContainerImpl.cs | 处理仓库内交互规则，仅支持与背包的单向操作 |
| 快捷栏 | FastBarSlotContainerImpl.cs | 处理快捷栏内交互规则，仅支持与背包的单向操作 |
| 装备栏 | EquipSlotContainerImpl.cs | 框架就位，具体实现待完善 |

## 四、后续优化方向

1. **UI 反馈**: 拖拽失败时给予视觉反馈（红色闪烁 + 原因提示）
2. **性能**: 目前每次操作触发 RefreshAll()，可优化为仅刷新受影响的 UI
3. **扩展**: 后续如需"装备槽"，按同架构添加 EquipSlotContainerImpl
4. **RemoveItem 精度**: 考虑添加 RemoveItemFromSlot(slotIndex) 方法
5. **交换逻辑**: 如需跨容器交换，应在容器实现中完整处理

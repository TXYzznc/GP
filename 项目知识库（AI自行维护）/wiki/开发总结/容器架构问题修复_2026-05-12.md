## 一、问题诊断（修复前）

诊断出 **5 个问题**，其中 2 个为 P0 数据丢失级别：

| # | 位置 | 问题 | 严重程度 | 状态 |
|---|------|------|---------|------|
| 1 | WarehouseSlotContainerImpl.cs:63-66 | 仓库内 SwapSlots 完成后又调用 RemoveItem，导致重复修改 | P0 数据丢失 | ✅ 修复 |
| 2 | FastBarSlotContainerImpl.cs:52-55 | 快捷栏内 SwapSlots 完成后又调用 ClearSlot，刚交换的物品被清空 | P0 数据丢失 | ✅ 修复 |

| 4 | WarehouseSlotContainerImpl.cs:36-40 | CanInteractWith 允许仓库↔快捷栏直接交互 | P1 | ✅ 修复 |
| 5 | WarehouseSlotContainerImpl.cs:71-95 | MoveToInventory 不支持交换（目标有物品时直接失败） | P1 | ✅ 简化 |

**问题根源**：原设计用容器类型决定是否清空源格子，实际上应基于目标格子状态决定——这是更清晰灵活的方式。

## 二、修复方案（已执行）

### Bug 1：仓库内部交换丢失数据

**文件**: `WarehouseSlotContainerImpl.cs:63-66`

```csharp
// 修复前（错误）
if (success)
    m_WarehouseManager.RemoveItem(fromSlotIndex, count);

// 修复后（正确）
if (success && targetContainer is not WarehouseSlotContainerImpl)
    m_WarehouseManager.RemoveItem(fromSlotIndex, count);
```

**影响**: 仓库内部交换时，不再清空源格子（数据由 SwapSlots 完整处理）。

---

### Bug 2：快捷栏内部交换丢失数据

**文件**: `FastBarSlotContainerImpl.cs:52-55`

```csharp
// 修复前（错误）
if (success)
    m_FastBarManager.ClearSlot(fromSlotIndex);

// 修复后（正确）
if (success && targetContainer is not FastBarSlotContainerImpl)
    m_FastBarManager.ClearSlot(fromSlotIndex);
```

**影响**: 快捷栏内部交换时，不再清空源格子。

---

### Bug 3 & 4：快捷栏 ↔ 仓库 不合理交互

**设计理由**: 快捷栏是"背包的快速访问栏"，物品流应通过背包中转，不应直接与仓库交互。

**FastBarSlotContainerImpl.cs**:
```csharp
// 修复后（删除 Warehouse 选项）
public override bool CanInteractWith(SlotContainerType otherContainerType)
    => otherContainerType == SlotContainerType.Inventory ||
       otherContainerType == SlotContainerType.FastBar;
```

**WarehouseSlotContainerImpl.cs**:
```csharp
// 修复后（删除 FastBar 选项）
public override bool CanInteractWith(SlotContainerType otherContainerType)
    => otherContainerType == SlotContainerType.Inventory ||
       otherContainerType == SlotContainerType.Warehouse;
```

---

### 设计改进：简化跨容器交换逻辑

**仓库→背包** 和 **快捷栏→背包** 的 MoveToInventory 方法原来有复杂的"目标物品回源容器"交换逻辑，现在简化为：

- 目标格子为空 → 存入
- 目标格子同种物品 → 堆叠
- 目标格子有不同物品 → **操作失败**（用户可先清空再操作）

**理由**: 
- 交换逻辑会导致数据竞争（RemoveItem 会操作新物品而非源物品）
- 简化后逻辑清晰，不影响用户体验
- 用户可先手动清空目标格子再操作

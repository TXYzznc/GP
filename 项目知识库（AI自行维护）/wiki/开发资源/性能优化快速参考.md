## 二、常见优化方案列表

### 2.1 渲染性能优化

#### 场景优化
```
问题：场景物体过多导致Draw Call高
解决方案：
✅ 启用GPU Instancing（相同模型批量渲染）
✅ 合并静态网格（Combine Mesh）
✅ 使用LOD系统（远处降低模型质量）
✅ 启用遮挡剔除（Occlusion Culling）
✅ 移除不可见的ColliderDebugging启用只在开发时
```

#### 粒子系统优化
```
问题：特效和粒子消耗大量GPU和CPU
解决方案：
✅ 限制粒子数量上限
✅ 使用粒子系统池化（复用而不是创建销毁）
✅ 降低粒子更新频率
✅ 使用Shader Graph替代复杂粒子
✅ 远处粒子禁用或降低质量
```

#### UI优化
```
问题：Canvas更新频繁，Rebuild开销大
解决方案：
✅ 使用多层Canvas分离静态和动态UI
✅ 启用Canvas Batch
✅ 避免频繁改变RectTransform
✅ 使用对象池管理UI元素
✅ 动态UI使用WorldSpace Canvas
```

### 2.2 内存优化

#### 资源加载优化
```
问题：一次性加载过多资源导致内存爆炸
解决方案：
✅ 实现AssetBundle系统（分块加载）
✅ 使用Addressables系统
✅ 及时卸载不用的资源
✅ 压缩纹理（使用ASTC或ETC格式）
✅ 减少分辨率（1080p → 720p可减少内存30%）
```

#### 代码内存优化
```
问题：频繁的GC Alloc导致帧率波动
解决方案：
✅ 避免在更新循环（Update）中New对象
✅ 使用对象池管理子弹、特效等动态对象
✅ 使用结构体而不是类（大量小数据）
✅ 避免使用LINQ（产生临时数组）
✅ 及时释放不用的回调（事件订阅）
```

#### 纹理内存优化
```
问题：高分辨率纹理消耗大量内存
解决方案：
✅ 图集合并（减少纹理数量）
✅ 使用Mipmap（逐级降分辨率）
✅ 压缩纹理（RGB DXT5）
✅ 删除未使用的纹理
✅ 针对不同平台使用不同分辨率
```

### 2.3 网络和数据优化

```
问题：数据包过大导致网络延迟
解决方案：
✅ 只发送必要的数据
✅ 使用增量更新（只发送变化）
✅ 压缩数据包
✅ 批量发送小数据包
✅ 减少同步频率（30Hz 而非 60Hz）
```

## 三、优化优先级排序

### P0（必须立即优化）

| 优先级 | 问题 | 影响 | 优化方案 | 预期收益 |
|--------|------|------|---------|---------|
| P0-1 | 探索场景加载 7.2秒 | 玩家体验 | 启用AssetBundle | -2.2秒 |
| P0-2 | 总堆内存 450MB | 低端设备崩溃 | 卸载不用资源 | -50MB |
| P0-3 | 战斗帧率波动 | 游戏卡顿 | GC优化 + 对象池 | 稳定30FPS |

### P1（周内优化）

| 优先级 | 问题 | 影响 | 优化方案 | 预期收益 |
|--------|------|------|---------|---------|
| P1-1 | 探索场景内存250MB | 性能问题 | 纹理压缩 | -50MB |
| P1-2 | Draw Call过高 | GPU压力 | GPU Instancing | -30% |
| P1-3 | UI频繁Rebuild | CPU压力 | 多Canvas分离 | -40% CPU |

### P2（月内优化）

| 优先级 | 问题 | 影响 | 优化方案 | 预期收益 |
|--------|------|------|---------|---------|
| P2-1 | 粒子性能不够 | 特效质量 | 粒子池化 | +更多特效 |
| P2-2 | LOD系统缺失 | 远处卡顿 | 实现LOD | +远景FPS |
| P2-3 | 网络包大小 | 延迟 | 压缩协议 | -20% 延迟 |

## 四、快速优化检查清单

### 渲染层检查

- [ ] 检查GPU Instancing材质
- [ ] 启用Occlusion Culling
- [ ] LOD距离配置合理

### 内存层检查
- [ ] Profiler查看最大内存用量

- [ ] 纹理是否压缩

- [ ] Update循环无New对象

- [ ] 事件订阅已清理
- [ ] 对象池已实现
- [ ] 定时器/协程无泄漏

### 加载层检查
- [ ] 场景加载时间 < 5秒
- [ ] 资源加载流程优化
- [ ] 进度条显示流畅
- [ ] 预加载策略合理
- [ ] 资源清理及时

## 八、常见陷阱

### ❌ 错误做法
```
1. 在Update中New List<>()
2. 每帧都查询所有对象
3. 使用Find()替代缓存
4. 忽视GC Alloc警告
5. 过度使用Coroutine
```

### ✅ 正确做法
```
1. 使用对象池复用对象
2. 缓存查询结果
3. 使用GetComponent()缓存
4. 目标GC Alloc = 0
5. 优先使用回调而非Coroutine
```

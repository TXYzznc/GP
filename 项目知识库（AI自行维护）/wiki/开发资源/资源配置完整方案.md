## 问题分析

### 问题 1: 缺失 290 个资源ID

**原因分析**:
- 项目中的资源ID 是从代码、配置表、数据表中的常量定义得出的（共 599 个）
- ResourceConfigTable 仅包含 309 个，缺少 290 个
- 缺失的 ID 中包含：
  - 实际使用但配置表中缺失的 ID（需补充）
  - 代码中定义但未被资源系统真正使用的常量（可忽略）
  - 自动生成的默认资源 ID（应标记为不存在）

### 问题 2: 美术资源大量缺失

**文件缺失分布**:
- ✅ 预制体框架存在（部分）
- ✅ 代码资源存在（Config、Scripts）
- ✗ UI 美术资源暂不存在（设计中）
- ✗ 卡牌图标暂不存在（1201-1226）
- ✗ Buff 图标暂不存在（1401-1411, 10001-10203）
- ✗ 棋子相关美术资源暂不存在

### 问题 3: 资源标记和追踪困难

**现状**: ResourceConfigTable 中的资源缺少：
- 使用来源标记（哪个表或模块使用）
- 文件状态标记（是否存在、是否完成）
- 优先级标记（哪些资源影响功能）

### 步骤 2: 为所有资源添加标记

#### 2.1 标记格式

在 ResourceConfigTable 的 **Name 列**末尾添加标记，格式为：
```
[原始资源名称] | [使用来源表] | [资源状态]

示例:
"开始游戏界面背景 | UI使用 | 资源暂不存在"
"神圣庇护-策略卡图标 | CardTable使用 | 资源暂不存在"
"棋子-后羿预制体 | SummonChessTable使用 | 资源暂不存在"
```

#### 2.2 标记类型说明

| 标记类型 | 含义 | 示例 |
|---------|------|------|
| `[表名]使用` | 该资源被哪个配置表或模块使用 | `CardTable使用`、`UI使用`、`BuffTable使用` |
| `资源暂不存在` | 资源文件在项目中找不到，可能还在设计/制作中 | `资源暂不存在` |
| `资源存在` | 资源文件已在项目中，可以正常使用 | `资源存在` |
| `路径待确认` | 资源存在但路径需要调整 | `路径待确认` |

#### 2.3 标记覆盖范围

- 现有资源（309 条）: 为所有资源添加使用来源标记
- 新增资源（259 条）: 添加完整标记（来源表 + 资源状态）

## 资源加载机制理解

### ResourceExtension.cs 加载流程

```csharp
// 1. 获取资源配置
var config = GetResourceConfig(configId);

// 2. 根据资源类型构建完整路径
string fullPath = GetFullAssetPath(config.Path, config.Type);
// 路径前缀根据 Type 自动添加：
// Type 1 (Sprite) → Sprites/
// Type 2 (Prefab) → Prefabs/
// Type 3 (Effect) → Prefabs/Entity/
// Type 4 (Material) → Materials/
// Type 5 (Texture) → Textures/
// Type 6 (ScriptableObject) → Config/
// Type 7 (Audio) → Audio/

// 3. 加载资源
var asset = await GF.Resource.LoadAssetAsync(fullPath);
```

### 资源路径规则

```
资源最终路径 = [类型前缀] + [配置表中的 Path]

示例:
Type=1, Path="Card/策略卡/神圣庇护.png"
→ 最终路径: Sprites/Card/策略卡/神圣庇护.png

Type=2, Path="角色/友方神话角色/后羿"
→ 最终路径: Prefabs/角色/友方神话角色/后羿
```

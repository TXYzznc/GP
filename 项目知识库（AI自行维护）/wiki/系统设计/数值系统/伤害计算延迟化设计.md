# 普攻伤害计算延迟化重构

## 问题回顾

原设计在 OnAttackExecute 时**提前计算伤害**，导致：

1. **无法支持多目标不同伤害** - 伤害在发射时就固定了，投射物打中多个目标时都是同一伤害值
2. **不符合业务逻辑** - 投射物可能打不中或半路被打掉，但伤害已经算好了
3. **目标属性变化无效** - 碰撞时无法根据目标的最新护甲/Buff调整伤害

**正确做法**：伤害应该在**实际碰撞时**才计算。

---

## 解决方案

### 1. 修改 HitContext（IHitDetection 层）

**新增字段**：`CalculateDamageCallback`

```csharp
/// <summary>伤害计算委托（每命中时调用，根据目标属性动态计算伤害）</summary>
/// <remarks>
/// 如果提供此委托，将用其返回值作为实际伤害，而不是使用 BaseDamage
/// 返回值：(伤害值, 是否暴击)
/// </remarks>
public System.Func<ChessEntity, (double, bool)> CalculateDamageCallback;
```

**好处**：
- 可选字段，不破坏现有逻辑
- 允许多个调用方定制伤害计算策略
- 支持投射物和AOE等多种检测器

---

### 2. 修改 HitDetectorBase.ApplyDamage()

**原逻辑**：直接使用 `context.BaseDamage`

**新逻辑**：
```csharp
// ⭐ 1. 动态计算伤害（支持根据目标属性调整）
double finalDamage = context.BaseDamage;
bool isCritical = context.IsCritical;

if (context.CalculateDamageCallback != null)
{
    (finalDamage, isCritical) = context.CalculateDamageCallback(target);
}

// 2. 使用 finalDamage 造成伤害...
target.Attribute.TakeDamage(finalDamage, ...);
```

**关键点**：
- 如果有委托，就调用委托并使用其返回值
- 否则降级到 `BaseDamage`（兼容旧逻辑）
- 在碰撞时动态计算，每个目标独立

---

### 3. 修改所有 NormalAttack 实现

#### 原做法（现在删除）：
```csharp
// ❌ 提前算伤害
double damage = CalculateDamage(caster, out bool isCritical);

HitContext context = new HitContext {
    BaseDamage = damage,  // 固定值，无法调整
    IsCritical = isCritical,
    ...
};
```

#### 新做法：
```csharp
// ✅ 构建上下文时不设伤害值
HitContext context = new HitContext {
    BaseDamage = 0,         // 占位符
    IsCritical = false,     // 占位符
    // ⭐ 设置伤害计算委托（延迟到碰撞时刻）
    CalculateDamageCallback = (hitTarget) =>
    {
        double damage = CalculateDamage(caster, out bool isCritical);
        DebugEx.Log("NormalAttackImpl",
            $"计算伤害 → {caster.Config?.Name} → {hitTarget.Config?.Name}: {damage:F1}");
        return (damage, isCritical);
    }
};
```

**修改的四个普攻类**：
1. `EvilSpiritNormalAttack.cs` - 近战
2. `HouyiNormalAttack.cs` - 投射物（后羿）
3. `ChangeNormalAttack.cs` - 投射物（嫦娥）
4. `EvilSoulNormalAttack.cs` - 投射物（恶魂）

## 工作流对比

### 原流程（问题设计）

```
OnAttackExecute 被触发
├─ 计算伤害 CalculateDamage(caster, out isCrit)
│  ├─ 读 caster 属性（攻击力/法强）
│  └─ 返回伤害值 = 属性 * 系数 + 基础伤
├─ 创建 HitContext，设置 BaseDamage = damage
├─ 启动碰撞检测 detector.Execute(context)
│
│  [碰撞检测中]
│  └─ 检测到碰撞 ApplyDamage()
│     ├─ 使用固定的 context.BaseDamage
│     └─ 造成伤害（此时无法考虑目标护甲变化）
└─ 动画完成 OnAnimationComplete
```

**问题**：
- ❌ 伤害在发射前就算好了
- ❌ 多目标时都是同一伤害值
- ❌ 目标属性变化无效

### 新流程（正确设计）

```
OnAttackExecute 被触发
├─ 创建 HitContext
│  ├─ BaseDamage = 0（占位符）
│  ├─ CalculateDamageCallback = lambda 函数（延迟计算）
│  └─ 启动碰撞检测 detector.Execute(context)
│
│  [碰撞检测中]
│  └─ 检测到碰撞 ApplyDamage(target, context)
│     ├─ ⭐ 调用 CalculateDamageCallback(target)
│     │  ├─ 获取 target 参数
│     │  ├─ 计算伤害（此时可考虑 target 护甲）
│     │  └─ 返回 (伤害值, 是否暴击)
│     ├─ 使用返回的伤害值造成伤害
│     └─ 下一个目标时重复此流程
└─ 动画完成 OnAnimationComplete
```

**优点**：
- ✅ 伤害延迟到碰撞时刻计算
- ✅ 多目标时每个目标独立计算
- ✅ 碰撞时可以获取目标的最新属性
- ✅ 支持投射物多段伤害场景

## 技术细节

### 委托签名

```csharp
public System.Func<ChessEntity, (double, bool)> CalculateDamageCallback;

// 调用
(double damage, bool isCritical) = callback(targetEntity);
```

### OnAttackExecute 的新职责

**原职责**：
1. ❌ 计算伤害
2. ✅ 启动碰撞检测
3. ✅ 播放特效
4. ✅ 回复蓝量

**新职责**：
1. ✅ 创建 HitContext（包含伤害计算委托）
2. ✅ 启动碰撞检测（不计算伤害）
3. ✅ 播放特效
4. ✅ 回复蓝量

## 兼容性说明

### 向后兼容

```csharp
// 如果某个调用方没有设置 CalculateDamageCallback
HitContext context = new HitContext {
    BaseDamage = 100,  // 直接设置
    CalculateDamageCallback = null,  // 默认为 null
};

// ApplyDamage() 中
if (context.CalculateDamageCallback != null) {
    (finalDamage, isCritical) = context.CalculateDamageCallback(target);
} else {
    // 降级到 BaseDamage
    finalDamage = context.BaseDamage;
}
```

**这意味着**：
- 旧代码（直接设置 BaseDamage）仍然可用
- 新代码（使用委托）会覆盖 BaseDamage
- 技能系统可以同时支持两种方式

## 投射物特殊处理

投射物检测器对每个碰撞目标调用 `ApplyDamage(target, context)`，所以委托会被多次调用（每个目标一次）。

```csharp
// 伪代码：ProjectileHitDetector
for each target in collision_targets {
    ApplyDamage(target, context);  // 每次调用时 CalculateDamageCallback 都被执行一次
}
```

**结果**：自动支持多目标不同伤害。

## 总结

这个重构**关键不是增加复杂性，而是移动伤害计算的时机**：

- **从**: OnAttackExecute 时（已知攻击者属性，未知目标）
- **到**: ApplyDamage 时（既知攻击者属性，也知目标属性）

这样才能支持**多目标时每个目标独立计算伤害**的正确业务逻辑。

# 棋子初始化机制

> **最后更新**: 2026-05-12  
> **状态**: 已完成  
> **相关文件**: 召唤师棋子初始化时机优化.md, 召唤师棋子注册问题诊断.md

## 一、问题诊断

### 症状描述

召唤师棋子（玩家阵营的棋子）没有被正确加到对战列表（CombatEntityTracker）中，导致：
- 各种系统无法正确查询玩家的棋子
- 技能目标选择不完整
- 棋子管理系统无法统一处理

### 问题根源

#### 1. 时序混乱

```
战斗准备阶段
├─ CombatPreparationState.ContinueCombatPreparationInitAsync()
│  └─ 第237行：CombatEntityTracker.Instance.Clear()  ← 清空追踪器
│  └─ 玩家通过UI放置棋子
│     └─ ChessPlacementManager.PlaceChessAsync()
│        └─ SummonChessManager.SpawnChessAsync()
│           └─ ChessEntity.Initialize()
│              └─ 第352行：尝试注册到CombatEntityTracker
│                 ? 此时CombatEntityTracker存在，但注册可能失败
```

#### 2. 召唤师棋子初始化时机太晚

**之前的设计**：
- 玩家角色在进入战斗准备阶段时，还是一个普通的 PlayerCharacter，不是"棋子"
- 只有进入战斗阶段（CombatState）时，才通过 CombatManager.StartCombat() 将其转化为"召唤师棋子"
- 导致玩家角色在战斗准备阶段无法被 CombatEntityTracker 追踪

#### 3. 棋子注册分散且不可靠

```
有多个地方都在尝试注册棋子：
├─ ChessEntity.Initialize() 内部自动注册
├─ SummonChessManager.SpawnChessAsync() 间接调用
├─ EnemySpawnManager 显式调用
└─ ChessPlacementManager 没有显式验证注册成功

问题：缺乏统一的注册机制和验证
```

## 二、解决方案

### 2.1 优化 1：提前初始化召唤师棋子

**目标**：将召唤师棋子初始化从战斗阶段提前到战斗准备阶段

**文件**：`Assets/AAAGame/Scripts/GameState/States/CombatPreparationState.cs`

**新增方法**：`InitializeSummonerChessForCombat()`

职责：
- 获取玩家角色和召唤师配置
- 动态添加必要的组件（BuffManager、ChessAttribute、ChessEntity）
- 调用 `chessEntity.InitializeAsSummoner()` 初始化棋子实体
- 绑定 HP 变化事件和代理状态
- 注册到 CombatEntityTracker

**调用时机**：
```csharp
CombatEntityTracker.Instance.Clear();
DebugEx.Log(..., "CombatEntityTracker 已准备就绪");

// ⭐ 初始化召唤师棋子（提前到战斗准备阶段，使其能被纳入棋子管理系统）
InitializeSummonerChessForCombat();  // 新增，第251行

await InitializeCombatManagersAsync();
```

**实现框架**：
```csharp
private void InitializeSummonerChessForCombat()
{
    var playerCharacter = PlayerCharacterManager.Instance?.CurrentPlayerCharacter;
    if (playerCharacter == null) return;

    // 初始化召唤师运行时数据
    SummonerRuntimeDataManager.Instance.Initialize();

    // 读取配置
    var summonerRuntimeData = SummonerRuntimeDataManager.Instance.GetRuntimeData();
    var summonerConfig = SummonerChessTable.Instance.GetConfig(summonerRuntimeData.ChessId);

    // 动态添加组件
    var buffManager = playerCharacter.GetComponent<BuffManager>();
    if (buffManager == null)
        buffManager = playerCharacter.AddComponent<BuffManager>();

    var chessAttribute = playerCharacter.GetComponent<ChessAttribute>();
    if (chessAttribute == null)
        chessAttribute = playerCharacter.AddComponent<ChessAttribute>();

    var chessEntity = playerCharacter.GetComponent<ChessEntity>();
    if (chessEntity == null)
        chessEntity = playerCharacter.AddComponent<ChessEntity>();

    // 初始化棋子实体
    chessEntity.InitializeAsSummoner();

    // 注册到追踪系统
    if (CombatEntityTracker.Instance != null)
        CombatEntityTracker.Instance.RegisterChess(chessEntity);

    DebugEx.Log("CombatPreparationState", 
        $"✅ 召唤师棋子已在战斗准备阶段初始化完成, ChessId={summonerConfig.ChessId}, HP={chessAttribute.CurrentHp}");
}
```

### 2.2 优化 2：显式注册玩家放置的棋子

**文件**：`Assets/AAAGame/Scripts/Game/Combat/Chess/ChessPlacementManager.cs`  
**位置**：第509-516行

**修改前**：
```csharp
var entity = await SummonChessManager.Instance.SpawnChessAsync(chessId, spawnPos, 0);
if (entity == null) { return; }

entity.gameObject.layer = m_ChessLayer;
CombatSessionData.Instance.ConsumePopulation(config.PopCost);

// 标记为已出战，但并未显式注册到CombatEntityTracker
ChessDeploymentTracker.Instance.DeployChess(instanceId, entity);
```

**修改后**：
```csharp
var entity = await SummonChessManager.Instance.SpawnChessAsync(chessId, spawnPos, 0);
if (entity == null) { return; }

entity.gameObject.layer = m_ChessLayer;
CombatSessionData.Instance.ConsumePopulation(config.PopCost);

// ⭐ 确保棋子被注册到战斗追踪系统（战斗准备阶段可能没有自动注册）
if (CombatEntityTracker.Instance != null)
{
    CombatEntityTracker.Instance.RegisterChess(entity);
    DebugEx.Log("ChessPlacementManager", 
        $"✅ 棋子已注册到CombatEntityTracker: {entity.ChessId}");
}

// 标记为已出战
ChessDeploymentTracker.Instance.DeployChess(instanceId, entity);
```

**原理**：
- 在棋子放置后，显式调用 RegisterChess() 确保注册成功
- 检查 CombatEntityTracker 是否存在（防守性编程）
- 即使 ChessEntity.Initialize() 中的注册失败，也能在这里补救

### 2.3 优化 3：简化 CombatManager

**文件**：`Assets/AAAGame/Scripts/Game/Combat/Core/CombatManager.cs`

**修改内容**：
- 删除重复的召唤师初始化逻辑（90行代码削减）
- 仅验证召唤师棋子是否已准备好
- 关键操作保留：BuildEnemyCache 和 InitializeSummonerSkillSystem

**修改前**：
```csharp
public void StartCombat()
{
    // 60-158行：大量召唤师初始化代码
    // 获取玩家角色、添加组件、初始化属性、注册到CombatEntityTracker等
    // ...（90+行）
}
```

**修改后**：
```csharp
public void StartCombat()
{
    // 验证召唤师棋子已准备好
    var summonerChess = CombatEntityTracker.Instance.GetChessList(0).Find(c => c.IsSummoner);
    if (summonerChess == null)
    {
        DebugEx.Error("CombatManager", "❌ 召唤师棋子未初始化");
        return;
    }

    // 构建敌方棋子缓存
    BuildEnemyCache();

    // 初始化召唤师技能系统
    InitializeSummonerSkillSystem();
}
```

## 五、风险分析

### 5.1 低风险点

#### 时序依赖 ✓
- CombatEntityTracker 在第238行已经准备好
- SummonerRuntimeDataManager.Initialize() 在战斗准备阶段被调用
- 所有依赖项都已准备

#### 重复调用 ✓
- 检查 chessEntity 是否已存在（AddComponent 会复用）
- ChessEntity.Initialize() 是幂等的
- 多次调用不会造成问题

#### 状态一致性 ✓
- RegisterSummoner 在此处调用，战斗阶段仅验证
- HP/MP 初始化一致
- 无重复初始化

### 5.2 需要关注的点

#### 战斗准备被中止

如果战斗准备被中止，需要确保召唤师棋子被清理：
- ✓ 现有的 OnLeave() 中会调用 DestroyAllChessInstances()
- ✓ CombatEntityTracker.Clear() 会清空所有注册

## 七、为什么敌方棋子没有这个问题？

敌方棋子生成在战斗状态进入后（CombatState.SpawnEnemiesAndEnableAI），此时 CombatEntityTracker 已经稳定存在，所以 ChessEntity.Initialize() 中的注册能够成功。

玩家棋子和召唤师棋子的不同之处：
- **玩家棋子**：生成于战斗准备阶段（时序不稳定）→ 需要显式注册
- **敌方棋子**：生成于战斗阶段（时序稳定）→ 自动注册足够

## 九、后续改进建议

### 9.1 统一注册机制

在 SummonChessManager 中直接注册，而不是依赖 ChessEntity 自己注册：

```csharp
public async UniTask<ChessEntity> SpawnChessAsync(int chessId, Vector3 position, int camp)
{
    // ... 生成逻辑 ...
    
    // ⭐ 在这里直接注册，保证成功
    if (CombatEntityTracker.Instance != null)
    {
        CombatEntityTracker.Instance.RegisterChess(chessEntity);
    }
    
    return chessEntity;
}
```

### 9.2 注册验证

添加断言确保注册成功：

```csharp
var chessEntity = await SummonChessManager.Instance.SpawnChessAsync(...);
Assert.IsTrue(CombatEntityTracker.Instance.Contains(chessEntity), 
    $"棋子 {chessId} 注册失败");
```

### 9.3 阵营检查

RegisterChess() 时根据阵营判断是否添加到敌方缓存（已在 AddEnemyToCache 中实现）

# 物品特殊效果架构

## 架构总览

当前项目的物品效果体系采用了 **三层分离架构**：
1. **配置层**（DataTable）— 各种效果参数和关联关系
2. **数据层**（Data Class）— ItemData / ConsumableData / TreasureData / EquipmentData
3. **执行层**（Effect Service）— GameEffectService / ItemEffectExecutor / ItemEffectFactory

---

## 配置表系统

### 1. **ItemTable**（基础物品表）
**作用**：存储所有物品的公共基础字段
```
字段：Id | Name | Type | Rarity | IsOnlyInGame | Description | IconId | 
      CanStack | MaxStackCount | SellPrice | Value | Weight
```
**说明**：
- 已精简，不再包含专有字段（CanUse、SpecialEffectId、SynergyIds 等）
- Type 字段指定物品分类（1=消耗品、2=任务道具、3=宝物、4=装备、5=虚拟物品）

---

### 2. **ConsumableTable**（消耗品表）
**作用**：存储消耗品特有数据
```
字段：Id | Name | ItemTableId | CanUse | UseEffectId
```
**关键关系**：
- `ItemTableId` → 对应 ItemTable.Id
- `UseEffectId` → 指向 SpecialEffectTable.ID
- CanUse 控制是否能使用（可设为False禁用某些消耗品）

**使用流程**：
```
玩家使用消耗品
  ↓
ConsumableItem.OnUse()
  ↓
读取 ConsumableData.UseEffectId
  ↓
ItemEffectExecutor.ExecuteEffect(useEffectId)
  ↓
查询 SpecialEffectTable
  ↓
执行对应效果（AddGold / RestoreHP / UnlockCard 等）
```

---

### 3. **TreasureTable**（宝物表）
**作用**：存储宝物特有数据
```
字段：Id | Name | ItemTableId | SpecialEffectId | SynergyIds | BaseAttributes | MaxDurability
```
**关键关系**：
- `ItemTableId` → 对应 ItemTable.Id
- `SpecialEffectId` → 指向 SpecialEffectTable.ID（宝物被装备/主动触发时的特殊效果）
- `SynergyIds` → 逗号分隔的 SynergyTable.ID 列表（参与的羁绊）
- `BaseAttributes` → JSON 格式属性（{"MaxHP":"500","CritRate":"15%"}）
- `MaxDurability` → 当前未使用（预留字段）

**宝物效果渠道**：
- **被动效果**（穿戴时）：BaseAttributes → 应用到棋子属性
- **主动效果**（触发时）：SpecialEffectId → 执行通用效果（目前未在代码中看到触发点）
- **羁绊效果**：SynergyIds → 与其他宝物满足条件时激活

---

### 4. **EquipmentTable**（装备表）
**作用**：存储装备特有数据
```
字段：Id | Name | ItemTableId | SpecialEffectId | BaseAttributes
```
**关键关系**：
- `ItemTableId` → 对应 ItemTable.Id
- `SpecialEffectId` → 指向 SpecialEffectTable.ID（目前未使用，预留位置）
- `BaseAttributes` → JSON 格式属性（{"Attack":"60","CritRate":"10%"}）

**装备效果应用**：
```
穿戴装备
  ↓
ChessEquipmentManager.EquipItem()
  ↓
ApplyEquipmentStats()
  ↓
遍历 EquipmentItem.BaseAttributes
  ↓
ApplyAttributeModifier() 应用到 ChessAttribute
  ↓
触发 ChessStateEvents.FireEquipmentChanged()
```

---

### 5. **QuestItemTable**（任务道具表）
**作用**：存储任务道具元数据
```
字段：Id | Name | ItemTableId
```
**说明**：
- 任务道具无特殊效果，仅用于流程标记
- 卸下装备时配置表引用

---

### 6. **SpecialEffectTable**（通用效果表）
**作用**：定义所有特殊效果的参数和行为
```
字段：ID | Name | EffectType | Description | BuffIds | SelfBuffIds | 
      Cooldown | IconId | Weight | EffectParams
```
**说明**：
- **EffectType**：1=增益 / 2=减益 / 3=控制 / 0=消耗品/自定义效果
- **BuffIds / SelfBuffIds**：应用给目标或自身的 Buff 列表（来自 BuffTable）
- **EffectParams**：JSON 格式参数，包含自定义效果类型和参数
- **Weight**：随机权重（目前未使用）

**效果类型示例**：
```
消耗品效果（EffectType=0，有 EffectParams）：
{
  "type": "AddGold",
  "min": 100,
  "max": 500
}

战斗特殊效果（EffectType=1~3，有 BuffIds）：
{
  "BuffIds": [2001],
  "SelfBuffIds": []
}
```

## 数据流转

### 加载流程
```
游戏启动
  ↓
ItemManager.LoadAllTables()
  ↓
├─ LoadItemTable()          → m_ItemDataDict<int, ItemData>
├─ LoadConsumableTable()    → m_ConsumableDataDict<int, ConsumableData> (key=ItemTableId)
├─ LoadTreasureTable()      → m_TreasureDataDict<int, TreasureData>      (key=ItemTableId)
├─ LoadEquipmentTable()     → m_EquipmentDataDict<int, EquipmentData>    (key=ItemTableId)
├─ LoadSpecialEffectTable() → m_EffectDataDict<int, SpecialEffectData>
├─ LoadAffixTable()         → m_AffixDataDict
└─ LoadSynergyTable()       → m_SynergyDataDict

ItemEffectFactory.RegisterAll()
  ↓
注册所有自定义效果：AddGold, RestoreHP, UnlockCard, ...
```

### 物品创建流程
```
ItemManager.CreateItem(itemId)
  ↓
GetItemData(itemId) → 获取基础配置
  ↓
根据 ItemData.Type 判断：
├─ Consumable → ConsumableItem(itemId, itemData, GetConsumableData(itemId))
├─ Treasure   → TreasureItem(itemId, itemData, GetTreasureData(itemId))
├─ Equipment  → EquipmentItem(itemId, itemData, GetEquipmentData(itemId))
├─ QuestItem  → QuestItem(itemId, itemData)
└─ Virtual    → VirtualItem(itemId, itemData)

UnlockDictionaryEntry(itemId, itemType) → 自动图鉴解锁
```

## 效果执行系统

### 三层执行架构

#### 层级 1：GameEffectService（战斗效果入口）
用于战斗系统中的普遍效果触发
```csharp
public bool Execute(int effectId, GameEffectContext context)
  ↓
查询 SpecialEffectData
  ↓
├─ 路径A：Buff 应用
│   ├─ ApplyBuffs() → BuffApplyHelper.ApplyBuff(buffId, target, ...)
│   └─ 自身 Buff
│
└─ 路径B：自定义效果
    ├─ ItemEffectFactory.Create(effectType)
    └─ IItemEffect.Execute(context)
```

#### 层级 2：ItemEffectExecutor（物品效果入口）
消耗品/物品使用时的效果执行
```csharp
public bool ExecuteEffect(int effectId)
  ↓
├─ 新架构：工厂模式 ItemEffectFactory.Create()
└─ 向后兼容：ExecuteEffectLegacy()
```

#### 层级 3：ItemEffectFactory（工厂注册表）
```
注册表：string effectType → Func<IItemEffect>

已注册效果类型：
- "AddGold"           → AddGoldEffect
- "RestoreHP"         → RestoreHPEffect
- "RestoreMP"         → RestoreMPEffect
- "AddExp"            → AddExpEffect
- "RecoverChessHP"    → RecoverChessHPEffect
- "ReviveChess"       → ReviveChessEffect
- "RandomEquipment"   → RandomEquipmentEffect
- "UnlockCard"        → UnlockCardEffect
```

## 当前架构的完整例子

### 消耗品使用
```
玩家使用 ID=1（钱包）
  ↓
ConsumableTable[1]: UseEffectId=1001
  ↓
SpecialEffectTable[1001]:
{
  ID: 1001,
  Name: "消耗品·随机金币",
  EffectType: 0,
  EffectParams: {"type":"AddGold","min":100,"max":500}
}
  ↓
ItemEffectFactory.Create("AddGold")
  ↓
AddGoldEffect.Execute(context)
  ↓
随机生成100-500金币，加入玩家背包
```

### 装备穿戴
```
穿戴装备 ID=10（石中剑）
  ↓
EquipmentTable[1]: ItemTableId=10, SpecialEffectId=4001, BaseAttributes={"Attack":"60","CritRate":"10%"}
  ↓
ChessEquipmentManager.EquipItem(chessId, equipmentItem, slotIndex)
  ↓
ApplyEquipmentStats()
  ↓
ChessAttribute.Attack += 60
ChessAttribute.CritRate += 10%
```

### 宝物装备（羁绊激活示例）
```
穿戴宝物 ID=7（八尺琼勾玉）
  ↓
TreasureTable[1]: BaseAttributes={"MaxHP":"500","CritRate":"15%"}
               SynergyIds=[3001]
  ↓
穿戴时立即应用 BaseAttributes
ChessAttribute.MaxHP += 500
ChessAttribute.CritRate += 15%
  ↓
检查羁绊激活条件（3001 号羁绊是否满足）
  ↓
若满足，激活羁绊效果（SpecialEffectTable[3001]）
```

## 当前问题与改进建议

### 现状评估
✅ **优点**：
- 配置表分离清晰，易于维护和扩展
- 工厂模式支持自定义效果的灵活注册
- 两层效果执行入口（GameEffectService 和 ItemEffectExecutor）满足战斗和物品两大场景

⚠️ **需要改进的点**：

1. **装备 SpecialEffectId 未使用**
   - EquipmentTable 有 SpecialEffectId 字段，但代码中完全未读取
   - 建议明确这是否是设计预留，还是应该被触发
   - 如果要支持"装备特效"（如主动触发的技能），需要在 ChessEquipmentManager 中补充逻辑

2. **宝物 SpecialEffectId 指向错误可能性**
   - TreasureTable 中 SpecialEffectId 和 SynergyIds 同时存在
   - SynergyIds 指的是羁绊 ID（SynergyTable.ID），而不是效果 ID
   - TreasureItem 中读取 SpecialEffectId，但从未在实际穿戴时触发
   - 建议明确宝物效果的触发时机（是被动应用还是主动触发？）

3. **BaseAttributes 解析的一致性**
   - ConsumableData / TreasureData / EquipmentData 都有 BaseAttributes 字段
   - 但只有装备 EquipmentItem 在 ApplyAttributeModifier 中实际应用
   - 建议规范化：是否消耗品和宝物的属性也应该应用到棋子上？

4. **缺少装备、宝物的 Buff 应用**
   - 当前装备和宝物只应用 BaseAttributes（数值加成）
   - 没有支持通过 BuffTable 的 Buff 应用（如"穿戴时获得某个 Buff"）
   - 建议补充：装备/宝物穿戴时可以绑定长期 Buff

5. **宝物的主动效果体系不完整**
   - TreasureItem.SpecialEffectId 已读取，但无触发入口
   - 建议补充：宝物在战斗中能否主动触发特殊效果？

## 建议的改进方案

### 方案 A：完善装备和宝物的 Buff 支持
在 ChessEquipmentManager 中补充：
```csharp
// 穿戴时同时应用 Buff
private void ApplyEquipmentStats(int chessId, EquipmentItem item)
{
    // 现有：应用 BaseAttributes
    ...
    
    // 新增：应用 Buff 效果
    if (item.SpecialEffectId > 0)
    {
        var effectData = ItemManager.Instance?.GetSpecialEffectData(item.SpecialEffectId);
        if (effectData?.BuffIds?.Length > 0)
        {
            foreach (int buffId in effectData.BuffIds)
            {
                BuffApplyHelper.ApplyBuff(buffId, entity, true, null);
            }
        }
    }
}
```

### 方案 B：宝物羁绊效果触发
在穿戴宝物时检查是否满足羁绊条件，若满足则触发：
```csharp
if (item.SynergyIds != null && item.SynergyIds.Count > 0)
{
    CheckAndActivateSynergies(chessId, item.SynergyIds);
}
```

### 方案 C：确认字段语义，优化配置
- **装备的 SpecialEffectId**：改名或明确只用于被动 Buff
- **宝物的 SpecialEffectId vs SynergyIds**：确认是否应分开为"主动效果"和"羁绊参与"

---

## 总结

当前系统的架构设计是 **清晰且可扩展的**，但有以下几个关键要点需要确认：

1. **装备和宝物是否都应该支持 Buff 应用？**
2. **宝物的 SpecialEffectId 何时触发？**
3. **BaseAttributes 的应用范围是只限装备还是也包括宝物和消耗品？**

一旦这些设计决策确认，架构可以进一步完善，形成一套统一、灵活的物品效果系统。

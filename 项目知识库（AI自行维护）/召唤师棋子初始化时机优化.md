# 召唤师棋子初始化时机优化

## 目标

将召唤师棋子（玩家角色）的初始化从**战斗阶段**提前到**战斗准备阶段**，使其能被纳入棋子管理系统统一管理。

## 问题背景

之前的设计中：
- 玩家角色在进入战斗准备阶段时，还是一个普通的 PlayerCharacter，不是"棋子"
- 只有进入战斗阶段（CombatState）时，才通过 CombatManager.StartCombat() 将其转化为"召唤师棋子"
- 这导致玩家角色在战斗准备阶段无法被 CombatEntityTracker 追踪，后续的棋子管理系统无法统一处理

## 解决方案

### 1. 新增初始化方法

**文件**：`Assets/AAAGame/Scripts/GameState/States/CombatPreparationState.cs`

新增方法 `InitializeSummonerChessForCombat()`，职责：
- 获取玩家角色和召唤师配置
- 动态添加必要的组件（BuffManager、ChessAttribute、ChessEntity）
- 调用 `chessEntity.InitializeAsSummoner()` 初始化棋子实体
- 绑定 HP 变化事件和代理状态
- 注册到 CombatEntityTracker

### 2. 调用时机

在 `CombatPreparationState.ContinueCombatPreparationInitAsync()` 中：
- 第238行：CombatEntityTracker 准备完毕
- **第251行**（新增）：调用 `InitializeSummonerChessForCombat()` ← 这里
- 第253行：初始化战斗管理器

```csharp
CombatEntityTracker.Instance.Clear();
DebugEx.Log(..., "CombatEntityTracker 已准备就绪");

// ⭐ 初始化召唤师棋子（提前到战斗准备阶段，使其能被纳入棋子管理系统）
InitializeSummonerChessForCombat();  // 新增

await InitializeCombatManagersAsync();
```

### 3. 简化 CombatManager

**文件**：`Assets/AAAGame/Scripts/Game/Combat/Core/CombatManager.cs`

修改 `StartCombat()` 方法：
- 删除重复的召唤师初始化逻辑（90行代码削减）
- 仅验证召唤师棋子是否已准备好
- 关键操作保留：BuildEnemyCache 和 InitializeSummonerSkillSystem

## 收益

### 1. 结构改进
- ✅ 所有棋子在战斗准备阶段就被注册到 CombatEntityTracker
- ✅ CombatManager.StartCombat() 职责简化
- ✅ 初始化逻辑集中在更早的阶段完成

### 2. 功能改进
- ✅ 战斗准备阶段可以统一查询所有棋子（包括召唤师）
- ✅ Buff/技能系统在战斗准备阶段就能引用召唤师棋子
- ✅ UI 预览可以包含召唤师信息

### 3. 代码改进
- ✅ 减少代码重复（删除 90+ 行）
- ✅ 提高可维护性（初始化逻辑集中）
- ✅ 更清晰的职责划分

## 风险分析

### 低风险点

1. **时序依赖**
   - ✓ CombatEntityTracker 在第238行已经准备好
   - ✓ SummonerRuntimeDataManager.Initialize() 在战斗准备阶段被调用
   - ✓ 所有依赖项都已准备

2. **重复调用**
   - ✓ 检查 chessEntity 是否已存在（AddComponent 会复用）
   - ✓ ChessEntity.Initialize() 是幂等的

3. **状态一致性**
   - ✓ RegisterSummoner 在此处调用，战斗阶段仅验证
   - ✓ HP/MP 初始化一致

### 需要关注

1. 如果战斗准备被中止，需要确保召唤师棋子被清理
   - ✓ 现有的 OnLeave() 中会调用 DestroyAllChessInstances() 和 CombatEntityTracker.Clear()

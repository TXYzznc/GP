# 召唤师棋子战斗注册问题诊断

## 问题描述

召唤师棋子（玩家阵营的棋子）没有被正确加到对战列表（CombatEntityTracker）中，导致各种系统无法正确查询和操作玩家的棋子。

## 问题确认

### 日志证据

从 GameTest_Log_2026-05-07_14-24-00.log 可以看到：

```
[14:23:48.805] [Log] [CombatState] CombatEntityTracker 已存在，当前已注册棋子数量: 
  阵营0=1（玩家阵营）
  阵营1=0（敌方阵营）
```

这表明进入战斗状态时，只有 **1个棋子** 被注册到阵营0，但实际上应该有：
- 1个召唤师棋子（系统自动创建）
- N个玩家放置的棋子（由玩家在战斗准备阶段放置）

## 根本原因分析

### 时序问题

```
战斗准备阶段
├─ CombatPreparationState.ContinueCombatPreparationInitAsync()
│  └─ 第237行：CombatEntityTracker.Instance.Clear()  ← 清空追踪器
│  └─ 玩家通过UI放置棋子
│     └─ ChessPlacementManager.PlaceChessAsync()
│        └─ SummonChessManager.SpawnChessAsync()
│           └─ ChessEntity.Initialize()
│              └─ 第352行：尝试注册到CombatEntityTracker
│                 ✓ 此时CombatEntityTracker存在，应该注册成功
```

### 但实际上注册失败的原因

在 `ChessPlacementManager.PlaceChessAsync()` 中：

```csharp
// ❌ 问题代码 - 第500-516行
var entity = await SummonChessManager.Instance.SpawnChessAsync(chessId, spawnPos, 0);
if (entity == null) { return; }

entity.gameObject.layer = m_ChessLayer;
CombatSessionData.Instance.ConsumePopulation(config.PopCost);

// 标记为已出战，但并未显式注册到CombatEntityTracker
ChessDeploymentTracker.Instance.DeployChess(instanceId, entity);
```

**问题：** 虽然 ChessEntity.Initialize() 中会尝试注册到 CombatEntityTracker（第352行），但这个注册有以下问题：

1. **竞态条件**：如果注册时 CombatEntityTracker 尚未准备好，会导致注册失败
2. **缺乏显式验证**：PlaceChessAsync 没有验证注册是否成功
3. **分散的注册逻辑**：有多个地方都在尝试注册棋子：
   - ChessEntity.Initialize() 内部
   - SummonChessManager.SpawnChessAsync() 中间接调用
   - EnemySpawnManager 中显式调用

## 解决方案

### 修复 1：在 ChessPlacementManager 中显式注册玩家棋子

**文件**：`Assets/AAAGame/Scripts/Game/Combat/Chess/ChessPlacementManager.cs`  
**行数**：第509-516行

```csharp
// 设置Layer
entity.gameObject.layer = m_ChessLayer;

// 扣除统帅值
CombatSessionData.Instance.ConsumePopulation(config.PopCost);

// ⭐ 确保棋子被注册到战斗追踪系统（战斗准备阶段可能没有自动注册）
if (CombatEntityTracker.Instance != null)
{
    CombatEntityTracker.Instance.RegisterChess(entity);
}

// 标记为已出战
ChessDeploymentTracker.Instance.DeployChess(instanceId, entity);
```

**原理**：
- 在棋子放置后，显式调用 RegisterChess() 确保注册成功
- 检查 CombatEntityTracker 是否存在（防守性编程）
- 这样即使 ChessEntity.Initialize() 中的注册失败，也能在这里补救

## 扩展思考

### 为什么敌方棋子没有这个问题？

敌方棋子生成在战斗状态进入后（CombatState.SpawnEnemiesAndEnableAI），此时 CombatEntityTracker 已经稳定存在，所以 ChessEntity.Initialize() 中的注册能够成功。

### 为什么之前没有发现？

- 玩家只放置了 1 个或 0 个棋子时，注册可能侥幸成功
- 如果玩家放置了多个棋子，中途会出现"索敌不到棋子"、"卡牌目标选择不完整"等现象
- 本次对战中，玩家可能只放置了 1 个棋子（嫦娥），所以没有立即暴露问题

## 后续改进建议

1. **统一注册机制**：在 SummonChessManager 中直接注册，而不是依赖 ChessEntity 自己注册
2. **注册验证**：添加断言确保注册成功
3. **阵营检查**：RegisterChess() 时根据阵营判断是否添加到缓存（已在 AddEnemyToCache 中实现）

> - 战斗结算：胜利→奖励 / 失败→惩罚

**关键代码（AI攻击缓存机制）**：
```csharp
// AI决策 - 缓存目标避免动画期间状态变化
private void TryAttack()
{
    m_CachedTarget = FindNearestEnemy();
    m_CachedDamage = CalculateDamage();
    m_Controller.PlayAttack(); // 触发动画
}

// 动画事件回调 - 从缓存读取执行
void AnimEvent_AttackExecute()
{
    if (m_CachedTarget != null && m_CachedTarget.IsAlive)
        m_NormalAttack.Execute(m_CachedTarget, m_CachedDamage);
}
```

**设计要点**：
- 攻击缓存：解决动画播放期间目标死亡/移动的问题
- UniTask：管理异步战斗流程，替代协程零GC
- 事件驱动：战斗各阶段通过事件通知其他系统

### Notes
战斗流程通过UniTask异步控制。核心设计是AI攻击缓存机制——决策时缓存目标和预计算伤害，动画事件触发时从缓存读取执行，确保逻辑正确性不受动画播放时间影响。

```csharp
// 并行异步加载50张配置表
var tasks = tableNames.Select(name =>
    GF.DataTable.LoadDataTableAsync(name, useBytes: true));

// 静态缓存 - 首次Miss后O(1)命中
public static DRBuffTable GetCached(int id) {
    if (!s_Cache.TryGetValue(id, out var row)) {
        row = GF.DataTable.GetDataTable<BuffTable>().GetDataRow(id);
        if (row != null) s_Cache[id] = row;
```

**动画状态机结构**：
```
Animator Controller - Base Layer:

├── Move（BlendTree: Speed参数混合）
```

**关键设计点**：
- 动画事件确保伤害判定与视觉精确同步
- BlendTree实现移动起停平滑过渡
- 7个状态覆盖棋子全部行为
- 攻击缓存机制配合AnimEvent使用

### Notes
动画系统通过Animation Event实现逻辑与视觉的精确同步。攻击动画在命中帧添加事件回调，确保伤害不会提前或延迟触发。移动使用BlendTree实现平滑过渡。
